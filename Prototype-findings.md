# Prototype Findings

This is a working file, not part of the design proper. It collects what the companion Unreal Engine 5.8 prototype, `MmoSurvivalGame`, has learned by building the design: places where an idea did not survive play, needed a number the documents do not give, or turned out to work better another way. The prototype reads this document as canon and never edits the design files on its own; instead, every session in it records its findings here, and the findings move into the design documents and their `(Technical)` companions once the user accepts them. See [AGENTS.md](AGENTS.md) for how this file fits the wider workflow, and [Design-backlog.md](Design-backlog.md) for questions the design itself still has to answer.

## How entries work

Each finding sits under the system it concerns, newest last. An entry names what the prototype tried, what play or testing showed, and the change it proposes, with links to the documents that change would touch. The date is the day the prototype established the finding, and the code path points at the prototype module where it can be seen. An entry stays here until its change has been written into the design or the user has rejected it; then it is removed, so this file holds only what is still waiting for a decision.

Modelling and content-creation sessions, including future ChatGPT and Codex sessions, may also add feedback here when the source design lacks information needed to produce the intended result, or when existing context is difficult to find. Name the missing or overlooked context, the assumption made, its observed consequence, and the document or link that would address it. Distinguish a missing design decision from an implementation mistake or a failure to read existing guidance. Such feedback remains a proposal until accepted; it does not authorise changes to the design documents themselves.
